# git-дисциплина этого проекта

Главная причина прошлых путаниц: бот сам пушит коммиты «Update bot data» в
`master` при каждом прогоне (шаг workflow "Commit bot data"). Локальная копия
от этого постоянно отстаёт от remote, а незакоммиченные правки «висят» между
сессиями. Чтобы это не всплывало, работаем по правилам ниже.

## Перед началом любой задачи

1. `git fetch` и проверь `git status -sb`:
   - если есть `behind` — сначала `git pull --rebase origin master`;
   - если есть незакоммиченные правки, которых тут не должно быть — разберись,
     чьи они, ДО начала правок, и скажи пользователю.
2. Только после этого правь код.

## После завершения задачи

1. Прогони проверки (pyflakes / sanity-тесты).
2. Сразу закоммить одну задачу одним коммитом с осмысленным сообщением — не
   оставляй «на потом» и не спрашивай «коммитить?», если правки уже сделаны.
3. Перед `git push` всегда `git pull --rebase origin master` (история линейная,
   конфликты приходят только из `data/` — бот их редко трогает) и затем `push`.
4. Убедись, что `git status -sb` показывает `## master...origin/master` без
   ahead/behind — это чистое состояние.

## Что куда

- `data/seen_urls.txt`, `data/state.json` — память бота, коммитится самим ботом
  во время прогонов. Не править руками.
- `assets/digest_cover.jpg` — постоянная обложка дайджеста, нужна в git.
- Код — обычные коммиты, как выше.
